## API Endpoints Reference

### 1. RAG & Chat
- `POST /api/chat`
  - **Request**: `{"query": "I manufacture stainless steel pressure cookers. Which BIS standard applies?", "user_role": "industry"}`
  - **Response**: `StructuredResponse` with `applicable_standards`, `certification_status`, `qcos`, `key_requirements`, `compliance_steps`, `sources`, `confidence`, `needs_clarification`.

### 2. Standards
- `GET /api/standards/search?q={query}&category={category}&industry={industry}&status={status}&limit=20`
- `GET /api/standards/{id}` (Lookup by standard ID or IS number like `IS 2347:2017`)

### 3. Regulatory Compliance
- `GET /api/compliance/{product}` (Direct compliance lookup for a given product)

### 4. Sources & Authority
- `GET /api/sources/` (List authoritative sources)
- `GET /api/sources/{id}` (Get source details)

### 5. History & Feedback
- `GET /api/history?session_id={id}&limit=50` (Query execution logs)
- `POST /api/feedback` (`{"query_id": "...", "rating": 5, "comments": "..."}`)

### 6. Administration & Ingestion
- `POST /api/ingestion/run` (Trigger sync and re-indexing)
- `GET /api/ingestion/status` (Health & counts of DB and vector store)
- `GET /api/health` (Application health check)

## Verified Test Categories

The backend has been verified against all 8 required evaluation scenarios:
1. **Natural Language Standard Lookup**: Identifies `IS 2347:2017` for pressure cookers.
2. **Certification Route & Scheme**: Resolves Scheme-I (ISI Mark) for electrical cables (`IS 694:2010`).
3. **Quality Control Order (QCO)**: Links electric irons (`IS 302-2-3:2021`) to DPIIT QCO `S.O. 2884(E)`.
4. **Industry Query**: Provides technical testing clauses, proof pressure values, and licensing roadmap.
5. **Consumer Safety Query**: Provides non-jargon safety guidance and ISI Mark verification steps.
6. **Ambiguous Query**: Detects missing product context and triggers clarification prompt.
7. **Unsupported Query (Zero Hallucination)**: Correctly answers "No standard found" with low confidence when asked about unsupported products.
8. **Exact IS Number Search**: Matches `IS 1293:2019` with complete clause citations.

## How to Run Locally

### 1. Install Dependencies
```powershell
pip install -r backend/requirements.txt
```

### 2. Configure Environment
Copy `.env.example` to `.env`:
```powershell
cp .env.example .env
```

### 3. Initialize Database & Qdrant Chunks
```powershell
python -m backend.database.session
python -m backend.knowledge.seed_data
python -m backend.ingestion.indexer
```

### 4. Start the FastAPI Server
```powershell
python -m backend.main
```
Or with Uvicorn:
```powershell
uvicorn backend.main:app --host 0.0.0.0 --port 8000 --reload
```
Interactive API documentation will be available at: `http://localhost:8000/docs`.

### 5. Run Automated Tests
```powershell
pytest -v
```

### 6. Run Live RAG Evaluation Suite
```powershell
python -m backend.tests.run_live_eval
```

## Known Limitations & Next Steps
- **Production Vector Store**: In local mode, Qdrant runs persistently via embedded SQLite storage engine (`./data/qdrant`). For high-throughput concurrent cloud deployment, set `QDRANT_URL=http://localhost:6333` with Docker.
- **Frontend Integration (Phase 3B)**: The backend contracts and schemas in `StructuredResponse` are stable and ready for React frontend binding.
